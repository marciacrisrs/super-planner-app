# UX 10 — Execution Roadmap

This roadmap is the working checklist for bringing the Super Planner UX to 10/10. It deliberately prioritizes usability over visual polish.

## Wave 1 — Foundation
- [x] Establish UX north star and autonomy language.
- [ ] Audit every primary screen against the north star.
- [ ] Establish semantic design tokens and reusable components.
- [ ] Establish UX writing rules and replace command/authority language.
- [ ] Establish accessibility baseline.

## Wave 2 — Agora / “o que faço agora?”
- [ ] Make the next-action recommendation the primary visual focus.
- [ ] Show available window and relevant next commitment.
- [ ] Show concise reason for the suggestion.
- [ ] Offer alternatives where meaningful.
- [ ] Allow accept, skip and choose another option with low friction.
- [ ] Handle no-good-option states gracefully.

## Wave 3 — Capacity / “o que cabe?”
- [ ] Make capacity understandable without productivity guilt.
- [ ] Explain why the day/week is tight or over capacity.
- [ ] Surface what is protected and what is deferred.
- [ ] Avoid dashboards that require maintenance.

## Wave 4 — Reality changed
- [ ] Provide an explicit “reorganizar” flow.
- [ ] Show before/after changes.
- [ ] Preserve fixed commitments and priorities.
- [ ] Show trade-offs.
- [ ] Review before applying consequential changes.
- [ ] Persist applied changes correctly.
- [ ] Support undo/recovery.

## Wave 5 — Week planning
- [ ] Make Organize Week proposal easy to understand.
- [ ] Show why items moved.
- [ ] Make conflicts and trade-offs obvious.
- [ ] Confirm application.
- [ ] Verify persisted result.
- [ ] Preserve original plan/recovery path.

## Wave 6 — Onboarding / first value
- [ ] Minimize required setup.
- [ ] Get user to first useful recommendation quickly.
- [ ] Demonstrate the “what fits now” value during onboarding.
- [ ] Avoid requiring users to understand planner terminology.
- [ ] Test empty, partial and realistic starting states.

## Wave 7 — AI trust and autonomy
- [ ] Make AI recommendations visually distinct from canonical state.
- [ ] Use short causal explanations.
- [ ] Expose meaningful alternatives.
- [ ] Never imply the AI owns the user's priorities.
- [ ] Keep domain validation authoritative.
- [ ] Make failures and uncertainty understandable.

## Wave 8 — Edge states
- [ ] Empty day.
- [ ] Overloaded day.
- [ ] Conflicting commitments.
- [ ] Late task.
- [ ] Cancelled commitment.
- [ ] Long-running task.
- [ ] Missing duration.
- [ ] Missing availability.
- [ ] Gateway unavailable.
- [ ] AI unavailable.
- [ ] User rejects recommendation.
- [ ] User repeatedly changes plan.

## Wave 9 — Design system + accessibility
- [ ] Typography hierarchy.
- [ ] Spacing system.
- [ ] Component consistency.
- [ ] Color semantics.
- [ ] Touch targets.
- [ ] Content descriptions.
- [ ] Contrast.
- [ ] State communication without color alone.
- [ ] Loading/error/empty states.

## Wave 10 — Validation
- [ ] Run #291 behavioral research.
- [ ] Run #260 beta with 5–10 users.
- [ ] Observe first value.
- [ ] Observe Agora usage.
- [ ] Observe trust/rejection behavior.
- [ ] Observe recovery after a broken plan.
- [ ] Measure planning administration burden.
- [ ] Record real user language.
- [ ] Re-score UX against the 10 quality gates.

## Stop rule

Do not start broad new AI features merely because they are technically interesting while a core UX gate remains red.
