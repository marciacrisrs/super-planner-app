# UX 10 — Primary Screen Audit

Use this checklist before considering a primary screen UX-complete.

## Home
- [ ] The screen communicates what the product helps with.
- [ ] The next useful action is obvious.
- [ ] The screen does not become a dashboard of everything.
- [ ] The user can reach Agora with minimal friction.

## Agora
- [ ] One primary recommendation has clear hierarchy.
- [ ] Available time is visible.
- [ ] Relevant upcoming commitment is visible.
- [ ] Duration is visible.
- [ ] Reason is concise and causal.
- [ ] Alternative is available when appropriate.
- [ ] Accepting/choosing is easy.
- [ ] Rejecting does not feel punitive.
- [ ] No recommendation does not produce a dead end.

## Day / Agenda
- [ ] Fixed commitments are visually distinct.
- [ ] Tasks do not compete visually with fixed commitments.
- [ ] Free capacity is understandable.
- [ ] Preparation and travel are not hidden when they affect feasibility.
- [ ] Overload is visible without guilt language.
- [ ] The day remains scannable.

## Week
- [ ] The week communicates capacity and priorities.
- [ ] Organization is a proposal, not an imposed decision.
- [ ] Trade-offs are visible.
- [ ] Changes can be reviewed before application.
- [ ] Application is persistent.
- [ ] Recovery/undo is available where appropriate.

## Create / Edit
- [ ] Required fields are minimal.
- [ ] Defaults are useful.
- [ ] The user understands which fields affect planning.
- [ ] Advanced configuration is optional.
- [ ] Saving does not unexpectedly reorder the user's life.

## Global
- [ ] Navigation is predictable.
- [ ] Terminology is consistent.
- [ ] Loading states explain what is happening.
- [ ] Errors tell the user what they can do next.
- [ ] Empty states are useful.
- [ ] Touch targets and contrast meet accessibility expectations.
- [ ] The product works without AI/gateway availability.
